# Changelog

All notable changes to TeumesseCastle are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Version 1.0.0 is defined as functional parity with PingCastle 3.0.0.0 (upstream commit
`d8f21e920278b82f243bdfe84d168d8040a0b96c`), rebranded and freed from every license/edition check.

## [Unreleased]

### Added
- Repository scaffolding: `NOTICE.md`, `CONTRIBUTING.md` / `CONTRIBUTING.fr.md`, `CODE_OF_CONDUCT.md`,
  `SECURITY.md`, `CLAUDE.md`, `docs/` (audit, decisions, progress).
- `Directory.Build.props` pulling the .NET Framework reference assemblies from NuGet so that the solution
  builds with the .NET SDK (`dotnet build`) without installing targeting packs.

- Teumesse branding: `assets/branding/` (logo, multi-size icon, generator script), new application icon,
  new favicon and navigation-bar logo in the HTML reports.

### Changed
- **Rebranding**: namespaces `PingCastle.*` become `TeumesseCastle.*`; the assembly, executable, solution
  and project are named `TeumesseCastle`; types and files containing "PingCastle" are renamed
  (`TeumesseCastleException`, `ITeumesseCastleReport`, ...). The assembly version is 1.0.0.0 and the product
  metadata reads "TeumesseCastle / Teumesse" with a double copyright line.
- User-facing strings: console banner, help, interactive menu, rule texts and report texts now say
  TeumesseCastle. The HTML report footer reads "Generated by TeumesseCastle" followed by
  "Based on PingCastle 3.0.0.0 by Vincent Le Toux (NPOSL-3.0)". Support messages point to the GitHub issue
  tracker. Every `pingcastle.com` link in code or reports now points to the GitHub repository (or was
  removed from the Content-Security-Policy); documentation links to Microsoft, ANSSI, MITRE, etc. are kept.
- Output file prefixes are unchanged (`ad_hc_*`, `ad_carto_*`, `ad_scanner_*`, `ad_export_*`) for
  compatibility with existing tooling; only the Azure AD report prefix changes from `pingcastlecloud_` to
  `teumessecastlecloud_`.
- The upstream `changelog.txt` and `license.rtf` moved to `docs/upstream/`; `testLDAPqueries.ps1` to `tools/`.
- `PingCastle.csproj` converted from the legacy project format to the SDK format. The target framework is
  unchanged (.NET Framework 4.5.2); the produced executable exposes the same embedded resources and the
  same types as PingCastle 3.0.0.0.
- `Newtonsoft.Json` is now a NuGet `PackageReference` (13.0.1) instead of a loose DLL next to the project.
- Every `.cs` file carries the original upstream copyright header plus the TeumesseCastle modification notice.
- Unused non-string sample entries (`Color1`, `Bitmap1`, `Icon1`) removed from the `.resx` files; the Azure AD
  sign-in dialog now takes its icon from the executable instead of an embedded resource.

### Removed
- **BREAKING CHANGE: the license mechanism is gone.** `License.cs` (RSA-signed license keys, editions
  Basic/Auditor/Pro/Enterprise, expiry date, domain limitation, customer notice), the embedded "Basic
  edition" key, the `--license` and `--debug-license` switches and the `LicenseSettings` section of the
  `.config` file are removed. The program no longer stops after an "end of support" date. Every feature
  that upstream reserved to paid editions is now available to everyone:
  maturity level and MITRE ATT&CK sections, password-age and last-logon distributions, AES/RC4 Kerberos
  analysis, maturity badges in the consolidation report, table export buttons, custom branding of the
  reports (`BrandLogo`/`BrandCss`/`BrandJs` appSettings), custom rule scores (`customRulesSettings`
  section, now declared in the `.config` file) and more than 25 honey-pot accounts.
- The "Compare with statistics" benchmark button of the HTML report, which posted the domain hash, scores
  and license key to the vendor's statistics server (`Report/ReportBenchmark.cs`).
- Post-build code-signing step bound to the upstream author's workstation (`signtool`, certificate
  "Ping Castle SAS").
